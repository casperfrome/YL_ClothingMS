## 在 PowerShell 中启动

需要 **JDK 25、Maven 3.9+、MySQL**。本机使用 **MySQL 9.7.2**，连接地址 `127.0.0.1:3306`、业务库 `YL_260924`、账号 `root`；数据库密码保存在不纳入 Git 的 `config/local.yml` 中。

1. 确认 MySQL 已启动。当前使用 Docker 容器 `mysql_9_7_2`（ID：`d5393750501d44ee9e0dce4c128b908f1688bbb233c30d5c1142509edb201c42`），若已停止，执行：

   ```powershell
   docker start mysql_9_7_2
   ```

   旧容器 `friendly_bohr` 保留用于迁移回退，应保持停止状态；两个容器都映射宿主机 3306 端口，不能同时按原配置启动。

2. 进入项目根目录，首次使用时复制配置模板：

   ```powershell
   Set-Location D:\AllForCareer\YL_ClothingMS
   [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
   if (-not (Test-Path .\config\local.yml)) {
       Copy-Item .\config\local.example.yml .\config\local.yml
   }
   ```

   在 `config/local.yml` 中填写真实的 `DB_PASSWORD`，并按需调整其他连接参数。已有配置无需重复复制；模板中的密码占位符不能直接使用。

3. 在项目根目录运行 `mvn spring-boot:run`。出现 `Started Application` 后，访问 **[http://localhost:8080](http://localhost:8080)**。

连接全新空库时，首次启动自动创建 `YL_260924`、执行数据库迁移并导入完整示例数据。已迁移的业务库包含原有数据及 `flyway_schema_history`，正常启动不会重复导入示例数据。无需手工执行 SQL，也无需安装前端依赖。首次 Maven 下载依赖需要网络；依赖就绪后，页面和图片均可本地使用。

在运行服务的 PowerShell 窗口按 **Ctrl+C** 正常停止。每个生成器下方的“保留生成的数据”决定该轮数据在关闭生成、切换模式及服务退出时是否保留；未保留批次会清理订单及该批次新增的用户、渠道关系。历史已保留批次及原有用户、商品、图片、渠道目录不受影响。重启后两个生成器均默认关闭，保留设置仍使用上次保存的值。不要同时用两个后端实例连接同一个业务库。

## 功能入口

- **商品管理**：新增和编辑款式、SPU 统一分类及描述；管理配色和图片；下探到“款 + 色 + 码 + 渠道”修改售价及上下架，可勾选本页记录进行批量操作。
- **品类管理**：新增、改名、删除单层品类。正在被商品引用的品类不能删除。
- **用户管理**：通过完整或部分手机号查询，修改基本信息，按已开通渠道和订单状态查看全部模拟订单。
- **渠道管理**：固定展示抖音、淘宝、京东、拼多多及关联数量，包含原有用户和新增模拟用户的开通关系。
- **模拟数据生成**：位于模拟订单开关左侧，每 500ms 新增 1–3 单、每 15 秒新增 1–2 个用户，并为每位新用户随机开通 1–4 个渠道。用户列表每 2 秒自动同步，保持筛选、输入和分页。
- **模拟订单生成**：右上角开关控制，每 500ms 新增 1–3 单，不新增用户。两个生成开关互斥，开启一个会按另一模式的保留设置停止该模式。浏览器关闭后后端继续运行，前端每 2 秒同步状态及其他页面更改的保留设置。
- **保留生成的数据**：两个模式分别记住设置，首次均默认关闭；下方提示“停止后保留”或“停止后清理”。数据模式保留本轮新增用户、渠道关系及订单，订单模式保留本轮新增订单。运行中可更改设置，以停止时最后成功保存的值为准；修改本身不删除记录、不重启生成，也不重置计数。停止时修改仅影响下次生成，历史已保留批次始终不受影响。

每次新建配色会自动创建五种尺码与四渠道共 20 条销售记录，默认全部下架。配色使用原生调色盘选择 1–2 个颜色。售价必须大于 0，最多两位小数。模拟订单只使用已上架商品及已开通对应渠道的用户；无有效组合时等待，条件恢复后继续。

两个模式中的新订单均从待付款开始，按固定的加速业务流程推进：

| 当前状态 | 停留时间 | 下一状态 |
|---|---:|---|
| 待付款 | 10 秒 | 90% 待发货，10% 已取消 |
| 待发货 | 30 秒 | 已发货 |
| 已发货 | 90 秒 | 90% 已完成，10% 已退款 |

概率按订单独立抽样；连续运行时正常完成约需 130 秒，终态不再更新。任一模式运行时，历史保留订单的未完成状态也会继续推进；两个模式均关闭时暂停流转。每个 500ms 周期按到期顺序推进，每阶段最多处理 100 单；数据库故障或积压可延迟流转，但不会压缩中间阶段。生成计数仅包含本轮新增数据，状态更新计数包含本轮推进的历史订单。订单保存成交时的商品和价格快照，不提供人工改状态入口。

首次订单与用户分别在开启后的 0.5 秒和 15 秒生成。生成时间间隔固定、批次数量在约定范围内随机，不提供调速设置。调度延误时跳过错过的生成时段，不集中补生成。无可售组合时仍生成用户并推进已有订单，恢复后继续下单。新老用户均可下单；用户列表保持原有 ID 升序，可通过总数和分页查看新增用户。

若后端遭遇断电或强制结束，无法执行退出回调；下一次启动会在接口开放前清理残留的未保留批次，保留其他批次，并停止两个生成器。模拟数据按批次归属保存在数据库，编辑用户资料不会改变清理归属；历史保留用户可继续参与新一轮订单生成，清理新批次不会误删其用户或渠道关系。数据库暂时不可用时，当前生成事务回滚，后续固定周期继续尝试；保留设置保存失败时不改变设置，模式切换清理失败时保持原模式。前端会重新同步服务端状态并显示错误。

Flyway V5 增加生成批次与两个模式的持久化保留设置。升级前的模拟订单、模拟用户归入未保留的历史批次，首次升级启动仍按原规则清理；升级后可通过保留开关保存新批次。本次不提供历史批次管理或手动删除入口。

## 示例数据

4 个品类、6 个款式、12 个配色、60 个 SKU、240 条渠道销售记录、24 张预览图、12 个随机模拟手机号用户及 30 条用户渠道关系。首次启动订单为零。

Flyway 迁移只执行一次，重启不重复初始化，不覆盖原有用户的人工编辑。商品和配色为逻辑删除；已删除款号仍保留，不能重复使用。仅被已删除商品引用的品类可以删除，已有订单快照不受影响。模拟数据功能可自动新增用户与渠道关系，本期仍不提供人工用户增删和渠道开通编辑。

图片格式支持 JPEG、PNG、WebP，单张不超过 5MB、2500 万像素，每配色最多 100 张。用户上传文件保存在项目的 `data/uploads`，数据库仅保存路径；重新打包不影响图片，请将该目录与数据库一起备份。示例图片随应用打包。

## 配置

运行参数集中在 `config/local.yml`，应用通过 `spring.config.import` 加载。此文件已被 `.gitignore` 排除，不进入 Git 或应用 JAR；仓库仅包含 `config/local.example.yml` 模板。

启动应用、运行 JAR 和执行测试时，工作目录均应为项目根目录；IDE 的 Working directory 也应设为项目根目录。部署 JAR 时，将填写好的 `config/local.yml` 放在运行目录的 `config/` 下。

同名环境变量优先于本地配置。本地文件可以省略，但此时必须提供 `DB_PASSWORD` 环境变量；数据库密码没有内置默认值。其余参数未配置时使用下表默认值：

默认连接经宿主机 3306 端口访问 `mysql_9_7_2`。迁移前后地址、库名及账号密码相同，因此连接值无需改变；不要将容器 ID 填入本机运行的 JDBC 地址。MySQL 数据保存在 `D:\AllForCareer\docker_volumes_mysql\260926`，项目上传图片仍保存在原 `data/uploads`。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8080` | HTTP 端口 |
| `DB_HOST` | `127.0.0.1` | MySQL 地址 |
| `DB_PORT` | `3306` | MySQL 端口 |
| `DB_NAME` | `YL_260924` | 业务数据库 |
| `DB_USER` | `root` | 数据库账号 |
| `DB_PASSWORD` | 无，必须填写 | 数据库密码；放在本地配置或环境变量中 |
| `UPLOAD_DIR` | `./data/uploads` | 持久化图片目录 |

例如端口被占用时：

```powershell
$env:PORT = "8081"
mvn spring-boot:run
```

应用仅监听 `127.0.0.1`，用于本机演示，无登录。连接字符集为 UTF-8，数据库使用 utf8mb4。Java、接口及页面采用 Asia/Shanghai；数据库会话时区为 +08:00，不修改 MySQL 全局时区。

## 项目结构

```text
src/main/java/com/yl/clothing/
  Application.java
  controller/     REST 路由、请求校验、响应包装
  service/        业务逻辑、事务、模拟器生命周期（直接使用业务类）
  mapper/         五组 MyBatis 数据访问接口
  entity/         业务表的 Java Bean 实体
    projection/   多表查询、统计与订单候选结果
  dto/            请求参数和类型化查询条件
  vo/             对外响应 record
  converter/      实体及查询结果到 VO 的显式转换
  common/         ApiResponse、PageResult、ErrorResponse、公共校验
  config/         静态资源、金额及时间序列化配置
  exception/      业务异常与全局异常处理
  enums/          订单状态枚举
src/main/resources/
  application.yml
  db/migration/   Flyway 建表与示例数据
  mapper/         MyBatis XML
  static/         HTML、CSS、ES Modules、24 张本地商品图片
src/test/         独立测试库配置与集成测试
docs/            OpenAPI、验收记录和示例图片来源
config/local.example.yml  可提交的配置模板
config/local.yml          本机实际配置（不进入版本控制）
data/uploads/    运行时上传图片（不进入版本控制）
```

请求经过 Controller → Service → MyBatis Mapper → MySQL。Controller 只调用 Service 并包装 HTTP 响应，Service 承担业务逻辑和事务，Mapper 使用明确的结果映射返回实体或类型化查询结果；Converter 显式转换为 VO，不直接向 API 暴露数据库实体。Service 直接使用业务类，不设置仅有单一实现的接口及 impl 层。

请求 DTO 使用 Bean Validation，查询条件也使用明确类型；业务数据不使用 Map。响应使用 ApiResponse<T> 和 PageResult<T>，仅错误中的 fieldErrors 保留 Map<String, String>。JacksonConfig 统一保留金额两位小数字符串、日期、+08:00 时间及 null 字段，前端及 REST API 格式与重构前一致。

SimulationCoordinator 用同一控制锁串行化两种模式的切换、生成、保留设置保存和批次清理；独立的 SimulationBatchService 保留 Spring 事务代理。单线程管理固定节拍，初始化依赖 Flyway 完成，服务销毁时在连接池关闭前停止调度并清理未保留批次；事务内依次删除订单、用户渠道关系、模拟用户及批次记录。订单候选先选择有可售商品的用户渠道关系，再选择该渠道商品，避免随机排序用户与商品的组合。图片上传同时维护数据库回滚和文件补偿，文件删除在事务提交后执行。

2026-09-24 的分层重构以 18 项测试建立兼容基线。本次模拟数据功能继续保留原接口字段契约，并扩展新接口、已发货状态和模拟器生命周期测试。分层测试约束 Controller、Service 和 Mapper 的依赖方向及类型边界。

## REST API

完整机器可读规范：[docs/openapi.json](docs/openapi.json)。无需鉴权，API 与页面同源，不需要 CORS 配置。

- 统一前缀 `/api`，JSON 使用 camelCase；成功响应 `{"data":...}`，删除成功返回 204。
- 商品、销售记录、用户和订单列表支持 `page`（从 1 开始）与 `pageSize`（默认 20，上限 100）。品类和四个固定渠道作为下拉选项/目录一次性返回。
- 分页内容为 `items、page、pageSize、total`。金额序列化为两位小数字符串，例如 `"159.00"`；时间带 `+08:00` 偏移。
- 参数错误、资源不存在、冲突分别返回 400、404、409；错误结构为 `code、message、fieldErrors`。
- 商品支持部分字段 PATCH。配色及用户表单 PATCH 提交完整可编辑字段组，`hex2` 与 `birthday` 可传 `null` 清空。
- 重复提交同一个模拟器开关状态为幂等操作，不清理、不重复调度。实际关闭或切换模式时，按被停止批次的保留设置处理，历史已保留批次不受影响；关闭已经关闭的开关不会停止另一模式。
- `GET/PUT /api/order-simulator` 和 `GET/PUT /api/data-simulator` 的状态均增加布尔字段 `retainData`，保留已有字段。`PUT` 继续使用 `{ "enabled": true/false }`；数据模式额外返回 `generatedUserCount` 和固定为 `15000` 的 `userIntervalMs`。
- 两个路径均新增 `PATCH`，接收必填且不可为 `null` 的布尔字段 `{ "retainData": true/false }`，返回更新后的完整状态。运行时同步修改当前批次的保留标志，停止时仅保存下次使用的设置；不重启生成或重置计数，保存失败则回滚。两个模式的设置独立持久化，首次默认 `false`，重复提交同值幂等。
- 两个模式每次服务启动均默认关闭。模式实际切换成功后重置本轮计数；`generatedCount` 始终表示本轮新增订单数，`updatedCount` 包含本轮推进的历史保留订单。订单查询支持 `SHIPPED`（已发货）筛选，订单与用户 JSON 字段不变。
